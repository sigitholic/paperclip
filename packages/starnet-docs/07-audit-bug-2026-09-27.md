# Audit bug: 27 Sep 2026

Audit ini mencatat bug dan gangguan yang ditemukan saat menjalankan Starnet Paperclip di **Windows native**
(Windows 11, UAC nonaktif, Node 24.19, Postgres di Docker) pada commit `d37ab681b` (`starnet/main`). Tujuannya: daftar
kerja untuk perbaikan berikutnya, bukan perbaikan itu sendiri.

## Ringkasan

- **Pembuatan agent-nya sendiri tidak rusak.** `POST /api/companies/:id/agents` berhasil untuk adapter Codex dan Cursor
  (diuji lewat API, agent uji lalu dihapus). Yang gagal adalah langkah di sekitarnya: sign-in AI connection, tes
  environment adapter, dan run pertama agent.
- **Agent Codex gagal karena model default tidak tersedia untuk paket ChatGPT "Go".** Penyebab ini sudah terbukti:
  dengan model `gpt-6-luna`, agent uji berhasil menyelesaikan tugas dari awal sampai akhir. Yang membuatnya sulit
  ditemukan: Paperclip hanya menampilkan pesan generik dan error asli tersembunyi di log internal Codex (B-01, M-05).
- Sebagian besar masalah bersifat **khas Windows** (perintah POSIX, path `E:`, UAC) dan ada di **kode core Paperclip**.
  Menurut aturan no-core-edits, perbaikannya lewat PR upstream, bukan commit di fork (lihat
  [05-aturan-kerja.md](./05-aturan-kerja.md)).
- Banyak baris WARN/404 di log ternyata **perilaku normal** (lihat bagian "Bukan bug"), jadi log dev terlihat lebih
  parah dari kondisi sebenarnya.

## B-01. Run agent Codex gagal: model tidak diizinkan paket ChatGPT

**Gejala.** Agent CEO hasil onboarding, **STARNET AGENT** (`codex_local`, company STARNET LABS), menjalankan issue
STA-1 tiga kali. Ketiganya `failed` dengan `errorCode: acpx_turn_failed`, pesan
`ACP agent reported a terminal service failure.` Setelah retry terbatas habis, agent di-pause, lalu di-terminate oleh
user dari UI (15:04).

**Akar masalah (terbukti).** Agent memakai login ChatGPT dari `C:\Users\ASUS\.codex\auth.json` (`auth_mode: chatgpt`,
paket **`go`**). Backend Codex (`https://chatgpt.com/backend-api/codex/responses`) menolak model yang diminta:

```
unexpected status 404 Not Found: The model `gpt-5.5` does not exist or you do not have access to it.
```

- Tanpa `adapterConfig.model`, Codex memakai default `gpt-6-astra`, yang tidak tersedia untuk paket ini.
- `gpt-5.5` ada di daftar model cache Codex untuk akun ini, tapi **tetap ditolak** server (404). Daftar model yang
  ditampilkan tidak bisa dipercaya sebagai daftar model yang benar-benar diizinkan.
- Codex mencoba ulang 5 kali lewat WebSocket, 5 kali lewat HTTP, lalu menyerah. Paperclip hanya menerima
  "terminal service failure" tanpa sebab (lihat M-05).

**Bukti percobaan** (agent uji "Diag Codex", company Starnet Demo, issue STAA-15):

| Run | Model | Hasil |
|---|---|---|
| `67b1d18f` | `gpt-5.5` | failed: 404 model tidak ada / tidak ada akses |
| `9348551f` | `gpt-5.5` | failed: sama |
| `89d9bcd8` | `gpt-6-luna` | **succeeded**: agent menulis komentar "OK" dan menandai issue `done` (1.190 token input, 23 token output, `billingType: subscription_included`) |

Error asli ditemukan di log internal Codex: tabel `logs` di
`~/.paperclip/instances/default/companies/<companyId>/codex-home/logs_2.sqlite`.

**Workaround (berlaku sekarang).** Set model secara eksplisit ke **`gpt-6-luna`** di setiap agent Codex (form agent,
field Model, atau `adapterConfig.model`). Alternatif: pakai AI connection dengan **API key** OpenAI, yang tidak
dibatasi paket ChatGPT.

**Temuan sampingan.** `config.toml` milik aplikasi Codex desktop ikut tersalin ke `codex-home` agent, termasuk
`[windows] sandbox = "elevated"`, `notify` ke `codex-computer-use.exe`, dan daftar project trusted pribadi. Dalam
percobaan ini hal itu tidak menggagalkan run, tapi berarti konfigurasi pribadi operator bocor ke lingkungan agent.

**Perbaikan yang diusulkan.**
- Starnet: tetapkan `gpt-6-luna` (atau model yang terbukti jalan) sebagai model default di template agent Starnet dan
  di [06-pengembangan-lokal.md](./06-pengembangan-lokal.md).
- Core (PR upstream): teruskan `sampling_error` dari Codex ke run log dan pesan error run (M-05). Tes environment Codex
  sebaiknya melakukan satu probe kecil ke model yang dipilih supaya masalah hak akses ketahuan sebelum agent dibuat.
  Pertimbangkan juga untuk tidak menyalin `config.toml` operator apa adanya ke `codex-home` agent.

## B-02. Sign-in langganan OpenAI tidak bisa selesai di Windows

**Gejala.** Di langkah koneksi saat membuat agent, memilih "OpenAI subscription" memunculkan perintah untuk dijalankan di
terminal. Status cek terus `sign_in_required`, dan saat Connect ditekan server membalas **422**
(`POST /ai-connections/local`).

**Akar masalah.** Perintah yang dibuat server (`server/src/services/local-ai-login.ts`, fungsi `presentAttempt`)
hanya cocok untuk shell POSIX dan bergantung pada CLI global:

```
(export CODEX_HOME='…' && mkdir -p "$CODEX_HOME" && codex -c 'cli_auth_credentials_store="file"' login --device-auth)
```

- `export`, `mkdir -p`, dan subshell `( … )` tidak jalan di PowerShell atau cmd.exe.
- Perintah memanggil `codex`, sedangkan mesin ini tidak punya `codex` global. Engine ACP memakai `codex-acp` bawaan
  repo, yang bukan CLI `codex`.
- Karena kredensial tidak pernah muncul di folder attempt, `complete()` lalu `readVerifiedLocalAiCredential()` melempar
  422. UI juga masih mengizinkan Connect ditekan walaupun cek terakhir belum `ready`.

**Workaround.** Pakai metode **API key** OpenAI (tidak lewat sign-in lokal). Atau pasang `npm i -g @openai/codex` lalu
jalankan perintah tersebut di **Git Bash**.

**Perbaikan yang diusulkan (PR upstream).**
1. Buat perintah sesuai platform (varian PowerShell di `win32`).
2. Preflight: cek apakah CLI provider ada di PATH sebelum menampilkan perintah, dan beri petunjuk instalasi kalau tidak.
3. UI: nonaktifkan Connect sampai cek mengembalikan `ready`.

## B-03. Adapter Cursor dan OpenCode gagal tes environment

**Gejala.** Memilih adapter Cursor di halaman New agent membuat `test-environment` dipanggil berulang dan hasilnya gagal.

**Bukti** (`POST /adapters/:type/test-environment` dengan config kosong):

| Adapter | Status | Alasan |
|---|---|---|
| `codex_local` | pass | Engine ACP bawaan repo, kredensial native terdeteksi |
| `claude_local` | warn | Engine ACP bawaan repo, auth belum lengkap |
| `cursor` | **fail** | `Command not found in PATH: "agent"` dan `CURSOR_API_KEY` tidak diset |
| `opencode_local` | **fail** | `Command not found in PATH: "opencode"` |
| `process` | fail (wajar) | Butuh `adapterConfig.command` |

Di mesin ini hanya ada `cursor` (launcher editor), bukan `agent` (Cursor Agent CLI).

**Masalah UX (core).** Agent tetap bisa dibuat walaupun tes environment gagal (terbukti lewat API). Hasilnya agent yang
tidak akan pernah bisa jalan. Petunjuk instalasi di pesan error berupa `curl … | bash`, yang tidak berlaku di Windows
native.

**Perbaikan yang diusulkan.**
- Lingkungan: pasang CLI yang dibutuhkan, atau pakai adapter yang lulus (Codex/Claude via ACP).
- Core (PR upstream): petunjuk instalasi per platform; peringatan yang jelas di UI sebelum menyimpan agent yang tesnya
  gagal.

## M-01. Install plugin dari path lokal crash di Windows

`server/src/services/plugin-loader.ts` memberi `--import <path absolut>` ke worker, dan Node di Windows menolak path
`E:\…` (`ERR_UNSUPPORTED_ESM_URL_SCHEME`, protokol `e:`). Akibatnya `POST /plugins/install` membalas 400 dan pack-isp gagal
aktif.

- **Status:** ditambal secara lokal dengan `pathToFileURL(DEV_TSX_LOADER_PATH).href`. **Belum di-commit dan jangan di-commit**
  (file core). Tambalan hilang kalau working tree di-reset.
- **Tindak lanjut:** sudah tercatat sebagai kandidat PR upstream #7 di [`STARNET_PATCHES.md`](../../STARNET_PATCHES.md).

## M-02. `demo-seed.mjs` diam saja di Windows

Guard `import.meta.url === \`file://${process.argv[1]}\`` tidak pernah cocok di Windows, jadi seed keluar tanpa melakukan
apa pun. Sudah diperbaiki dengan `pathToFileURL(process.argv[1]).href` di
`packages/starnet-devkit/scripts/demo-seed.mjs` (milik Starnet). **Status: belum di-commit**, siap masuk PR.

## M-03. Script pnpm gagal di cmd.exe

Beberapa script memakai `mkdir -p` dan sintaks POSIX lain, sedangkan pnpm di Windows menjalankannya lewat cmd.exe.
Workaround: `npm_config_script_shell='C:\Program Files\Git\bin\bash.exe'` sebelum `pnpm dev`. Mengubah `.npmrc` di root
termasuk edit core, jadi opsi yang bersih adalah PR upstream (script lintas platform) atau cukup didokumentasikan.

## M-04. Embedded Postgres menolak jalan saat UAC nonaktif

Embedded Postgres menolak jalan dengan pesan "administrative permissions". Workaround yang dipakai: Postgres di Docker
(`paperclip-postgres`, port `127.0.0.1:5441`). Sudah didokumentasikan di [06-pengembangan-lokal.md](./06-pengembangan-lokal.md).

## M-05. Detail error run agent ditelan

Dua tempat membuat kegagalan tidak bisa didiagnosis:

1. `server/src/services/heartbeat.ts` (sekitar baris 25925):
   `managedAiRuntime.cleanup().catch(() => logger.warn({ runId }, "AI connection refresh or cleanup failed"))`.
   Objek error dibuang, jadi log hanya berisi kalimat tanpa sebab. Warning ini muncul di **setiap** run STARNET AGENT.
2. Adapter ACP hanya meneruskan `ACP agent reported a terminal service failure.` tanpa pesan asli dari Codex, dan
   log stream ACPX yang dirujuk sesi tidak ditemukan di disk. Pesan aslinya (404 model tidak ada / tidak ada akses,
   lihat B-01) hanya ada di `codex-home/logs_2.sqlite`. Menemukan penyebab B-01 butuh query SQLite manual.

**Perbaikan yang diusulkan (PR upstream):** sertakan `err` di log warning (tidak perlu privacy review karena ini log
lokal, bukan Telemetry). Teruskan pesan error asli agent ACP ke run log (`heartbeat_run_events`).

## M-06. Office Chat 502 selama restart server

Setelah server restart, UI langsung memanggil `POST /plugins/<office-chat>/data/thread`. Server sudah menerima request
(`14:28:41`) sebelum worker plugin selesai diaktifkan (`14:28:42`), sehingga membalas **502** "No worker registered".
Setelah worker siap, request berhasil. Usulan: core membalas 503 dengan `Retry-After` selama plugin masih diaktifkan, dan
UI plugin melakukan retry.

## M-07. Sign out 404 di mode `local_trusted`

Di mode `local_trusted` rute `/api/auth/sign-out` tidak terpasang, tapi UI tetap menampilkan tombol Sign out. Menekannya
menghasilkan 404 dan error di console. Usulan: sembunyikan tombol atau balas no-op di mode ini.

## M-08. Halaman Apps memanggil `/api/tool-connections/byo`

Log menunjukkan `GET /api/tool-connections/byo` beserta `/catalog`, `/grants`, dan `/installs` berulang dengan 404. Di UI,
rute `apps/byo` ditangani `AppsConnect`, tapi `apps/:connectionId/:tab` ditangani `AppDetail`. Artinya kunjungan ke
`/apps/byo/<tab>` membuat `AppDetail` menganggap "byo" sebagai ID koneksi. **Perlu reproduksi** untuk tahu link mana yang
mengarah ke URL itu.

## M-09. "Organization not found" saat URL dibuka langsung

Membuka `http://127.0.0.1:3100/STAA/office-chat` langsung (reload atau tautan) sempat menampilkan halaman
"Organization not found / No organization matches prefix STAA" sebelum daftar company selesai dimuat. Setelah data
termuat, halaman yang benar muncul. Usulan upstream: tampilkan status memuat sampai daftar company siap, jangan langsung
404.

## OC-1. Office Chat tidak selaras (diperbaiki)

**Temuan sebelum perbaikan.**
- Tinggi kontainer di-hardcode `calc(100vh - 120px)`, padahal host menambah header, tombol Back, dan padding. Kontainer
  meluap 16px dari viewport, muncul scrollbar ganda, dan kotak input terpotong.
- Warna di-hardcode (`#2563eb` biru), tidak mengikuti tema netral Paperclip atau mode terang/gelap. Ikon sidebar berupa
  emoji. Jam tampil dalam format Inggris ("2:59:34 PM").
- Router hanya berbasis kata kunci. "selamat siang" dan "oke buat beberapa agent…" sama-sama dibalas template
  "Dicatat…", dan tidak ada agent LLM yang pernah dilibatkan. Kata pembuka seperti "oke"/"bro" membuat kata kerja tidak
  dikenali.
- "STAA-8 selesai ✅" bisa tampil sebelum hasil kerja agent, karena catatan status dicap waktu server, bukan waktu
  komentar.

**Perbaikan** (`packages/plugins/starnet-office-chat`, milik Starnet):
- UI: tinggi dihitung dari ruang viewport yang tersisa, semua warna memakai token tema host (`--primary`, `--muted`,
  `--border`, dll.), jam `id-ID` (`14.59`), ikon sidebar SVG bergaya lucide dengan kelas yang sama seperti item nav host,
  dan daftar pesan otomatis turun ke pesan terbaru.
- Router: sapaan dijawab langsung beserta daftar agent aktif. Pesan yang tidak cocok aturan diteruskan ke **agent
  default** (role `ceo`, lalu judul "kepala/chief/manager", lalu agent LLM pertama; agent `process` tidak pernah dipilih).
  Kata pembuka dibuang sebelum pencocokan.
- Thread: catatan status selalu diletakkan setelah balasan terakhir agent untuk issue yang sama. Catatan `in_progress`
  dihapus karena dobel dengan "mulai mengerjakan…".
- Brief ke agent meminta jawaban singkat dalam Bahasa Indonesia.
- Data: agent **Kepala Kantor** (`codex_local`, `gpt-6-luna`, role `ceo`) dibuat di Starnet Demo sebagai penerima default.

**Verifikasi.** 17 test plugin lulus (termasuk test baru untuk agent default, sapaan, kata pembuka, dan urutan status),
typecheck dan build lulus. Uji langsung: "selamat siang" dijawab dengan daftar agent; pertanyaan bebas menjadi STAA-16
untuk Kepala Kantor, yang menjawab 3 poin dalam Bahasa Indonesia dalam sekitar 50 detik, lalu "STAA-16 selesai ✅" tampil
setelah jawabannya. Di browser: tidak ada overflow (`main` scrollHeight = clientHeight) dan tombol memakai warna tema.

## L-01. Warning AJV pada skema config pack-isp

`strict mode: missing type "number,string" for keyword "format" at "#/properties/mikrotikPassword"` (dan
`genieacsPassword`). Di `packages/plugins/starnet-pack-isp/src/manifest.ts`, kedua field hanya punya
`format: "secret-ref"` tanpa `type`. Plugin lain (misalnya `sandbox-providers/modal`) memakai
`type: "string", format: "secret-ref"`. **Mudah diperbaiki langsung di fork** (milik Starnet).

## L-02. Warning "Could not render agent avatar"

`ERR_STREAM_UNABLE_TO_PIPE` di `server/src/routes/agent-avatars.ts` muncul saat browser membatalkan unduhan avatar (pindah
halaman atau gambar diganti). Tidak ada dampak ke data; request berikutnya 200. Usulan upstream: jangan log sebagai WARN
untuk error "client closed".

## S-01. Default Codex tanpa sandbox

Agent `codex_local` yang dibuat lewat API mendapat `adapterConfig.dangerouslyBypassApprovalsAndSandbox: true` secara
default. Ini keputusan upstream, tapi untuk agent NOC yang nantinya menyentuh perangkat produksi, Starnet sebaiknya
menetapkan kebijakan sendiri (misalnya tool gateway deny-by-default dan approval) dan tidak mengandalkan default ini.

## D-01. README devkit salah menyebut branch default

`packages/starnet-devkit/README.md` menyebut branch default `master`, padahal branch default fork adalah `starnet/main`.

## Bukan bug (noise yang wajar)

Baris log berikut terlihat seperti error, tapi sudah diperiksa dan memang perilaku yang disengaja:

| Log | Penjelasan |
|---|---|
| `POST …/tools/profiles/:id/bind 409` | Seed dijalankan ulang; `demo-seed.mjs` sengaja menangkap 409 sebagai "sudah terikat". |

| `GET …/claude-oauth-token-status 404` | Rute ada; 404 berarti belum ada token Claude OAuth. |
| `GET /heartbeat-runs/:id/log 404` di awal run | UI mem-poll sebelum file log run dibuat. |
| `bundled plugin bundle not present … E:\app\…` | Path image Docker (`/app`); di dev lokal memang dilewati. |

| `periodic heartbeat recovery changed assigned issue state` | Retry terjadwal dipromosikan; ini mekanisme recovery normal. |

## Urutan perbaikan yang disarankan

1. **B-01 (penyebab sudah ditemukan).** Pakai model `gpt-6-luna` di semua agent Codex, lalu jadikan default di
   template agent Starnet. Setelah itu kerjakan M-05 supaya error serupa langsung terlihat di UI.
2. **B-02 workaround.** Pakai metode API key OpenAI untuk AI connection sampai perbaikan upstream tersedia.
3. **Commit perbaikan milik Starnet:** M-02 (sudah siap), L-01, D-01, plus dokumen ini, dalam satu PR kecil.
4. **Paket PR upstream untuk Windows:** M-01, B-02, M-03, M-05, M-06 (M-07 dan L-02 opsional).
5. **B-03 / UX:** putuskan adapter standar Starnet di Windows (Codex/Claude via ACP) dan dokumentasikan di
   [06-pengembangan-lokal.md](./06-pengembangan-lokal.md).

- Memanggil `POST /adapters/:type/test-environment` untuk lima adapter di company Starnet Demo.

- Membaca detail, event, dan log tiga run STARNET AGENT yang gagal, serta file sesi ACP-nya.

- Tindak lanjut B-01: membuat agent uji "Diag Codex" dan issue STAA-15, menjalankan tiga run (dua `gpt-5.5`, satu
  `gpt-6-luna`), dan membaca log internal Codex di `codex-home/logs_2.sqlite`.

**Tidak dilakukan:** `pnpm test:run` / typecheck seluruh repo, dan pengujian UI di browser.
